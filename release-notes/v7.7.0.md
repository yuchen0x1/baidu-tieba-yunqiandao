# V7.7.0：通知可靠性与网页版统一分发

> GitHub 发布：2026-11-13（Asia/Shanghai）。本文保留本版当时的行为与兼容说明；当前部署只维护网页版，安装与升级以最新文档为准。

## 📢 版本概述

通知失败或渠道关闭时不再误报已发送，提醒和报告保留恢复后的重试机会。项目统一提供网页版部署包，不再单独分发 Windows 版；同时补齐历史版本日志并清理过时的开发资料。本版无数据库结构迁移。

## ✨ 新增功能

- **最近推送结果**：个人设置显示每个渠道最近一次推送的结果与时间。

## 🔧 改进与优化

- **通知发送判定**：HTTP 通知先检查响应状态，再检查渠道业务结果；重定向、鉴权失败、限流、服务异常和畸形响应不再伪装成功，通用 Webhook 支持空的 204 响应。
- **失败重试机会**：失败提醒只在邮件服务接受后记录当日已发送；日报未选渠道或发送失败时回退个人邮箱；周报失败或跳过不再阻断后续六天的发送机会。
- **监控摘要确认**：帖子监控摘要只确认本次接受的最多 30 条记录，未发送批次继续保留，避免漏报。
- **日报统计**：按成功与失败分别计数，零点配置有效，统计明确显示签到尝试次数；失败提醒不再把后续成功消息当成最近失败原因。
- **界面**：手机表单纵向排列，深浅主题下状态与标题更清晰。

## 🔒 安全与兼容性

- 钉钉、企业微信、飞书回调统一使用公开地址校验和 DNS 固定，拒绝内网及非公开目标；错误提示不再回显原始响应体或异常中的敏感信息。
- 管理员测试通知改为 POST 表单与 CSRF 校验，旧 `setting.php?mod=admin:testnotify` GET 链接返回 405；渠道未启用时明确显示未发送。
- **仅维护网页版**：统一发布 `tieba-cloud-sign-web-v7.7.0.zip`，Docker 与传统 PHP 环境部署同一网页版，不提供桌面客户端、移动 App 或单独 Windows 发行包；更新器优先选择 Web 包，并保留对历史网页包旧名称的读取兼容。
- 部署包排除测试、旧报告、截图、开发工具和实例资料，保留统一迁移器、安装模板与访问保护文件；完善 29 个版本或历史开发批次的日志。

## 🔄 升级与数据迁移

- 从 V7.6.0 升级没有新增数据库结构迁移，仍需通过根目录 `upgrade.php` 或 `php tools/migrate.php up` 同步版本；升级前备份，常驻调度进程升级后需重新加载代码。
- 相关任务和个人订阅需保持启用，失败项才会在任务后续执行时重试；依赖内网机器人代理的配置需调整为受支持的公开目标。
- 较旧更新器在 GitHub API 限流时仍可能按旧资产名称发现更新：请等待配额恢复、配置只读 `UPDATE_GITHUB_TOKEN`，或从本页下载 Web 包手动升级；不再额外发布旧名称的 Windows 包。
- 提供 SHA-256 校验文件和更新清单，未配置 detached 发布签名；强制要求签名的站点需使用符合其信任策略的部署流程。

## ⚠️ 已知问题

- 服务接受不等于设备收件或用户阅读；当前机制不承诺进程崩溃情况下的消息恰好一次投递，也未增加实时监控消息的持久队列或跨日补发。
