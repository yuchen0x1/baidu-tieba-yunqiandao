# 百度贴吧云签到 V7.0

> Git 记录日期：2026-09-06；本次未查到对应 GitHub Release，不把该日期当作发布日期。本文保留本版当时的行为与兼容说明；当前部署只维护网页版，具体以最新安装文档为准。
> 数据库版本 6.6 → 7.0（无破坏性结构变更）。全新安装直接使用安装向导即可；从 6.6 升级请看文末「升级与数据迁移」。

## 📢 版本概述

V7.0 是一次升级治理与架构收口版本：统一迁移器、版本门禁、开放 API 合同与插件 ABI 检查在此版本建立，数据库访问全面参数化收敛，调度与备份恢复链路补齐真实数据库集成测试。

## ✨ 新增功能

- **统一迁移器**（`lib/class.migrator.php`）：`schema_migrations` 升级为完整状态模型（checksum/状态/起止时间/批次/错误信息），执行前获取库级迁移锁，防 Web/CLI/容器并发；失败记录可恢复状态，修复后重跑即续走；任一迁移未全部成功绝不更新 `core_version`；已应用迁移被改写时 checksum 校验阻断。
- **版本门禁**：7.0 仅允许从 6.6 升级，更低版本明确阻断并引导先走旧升级链；管理员可访问 `/setup/update6.6to7.0.php`，或服务器执行 `php tools/migrate.php up`。
- **7.0 基线迁移**（007000）：校验 6.6 必备核心表齐全（缺失即失败，不猜不跳），幂等补齐调度结构。
- **开放 API 合同（v1）**（`lib/api-contract.php`）：所有响应携带 `api_version`；错误统一为 `{error, code, api_version}` 与稳定错误码（`missing_token`/`rate_limited`/`forbidden_user_token` 等）；权限矩阵单一事实源同时驱动门禁、openapi 文档与 README 表格，并有合同守卫测试双向防漂移。
- **插件 ABI**：启用插件前强制兼容检查（manifest 完整性 + 云签到最低版本 + PHP 最低版本），不满足拒绝启用并给出原因。
- **常驻调度模式（可选）**：`php do.php --pw=密码 --loop[=间隔秒]`（默认 30 秒，上限 600），复用 runall 的防重入锁/排程/退避机制，与 cron 触发天然互斥；适合无 crond 的 Windows 部署。

## 🔒 安全与兼容性

- **更新器安全**：在线更新安装前强制校验发布包 SHA-256（Release `digest` 或 `.sha256` 附件），拿不到可信摘要或哈希不符直接拒绝覆盖安装（ZIP 魔数不再作为完整性依据）。
- **注入面收敛**：`ajax.php` / `setting.php` / `api.php` 全部 SQL 参数化（含账号绑定、扫码登录、批量导入）；新增 `safe_table_name()` 白名单，来自数据库的动态表名统一过防；CI 守卫阻止插值拼接 SQL 回归。
- **⚠️ 行为变更（API）**：HTTP 方法严格化，方法不符统一返回 405。此前用 GET 调用 `sign` 等写接口会照常执行，现在请改用 POST。
- **⚠️ 配置变更（Docker）**：更新令牌命名由 `UPDATE_GITHUB_TOKEN` 统一为 `UPDATE_GITEE_TOKEN`（原变量失效，请同步修改部署环境变量）。
- Composer 平台要求补齐 `ext-zip` / `ext-openssl` / `ext-session`；OpenSSL 与 ZipArchive 在环境检查中升级为「必须」。

## 🐛 问题修复

- 修复备份导出丢失 NULL 值的问题（可空列此前导出为空字符串，恢复后 NULL→'' 静默失真）。
- 修复安装模板缺少 `api_rate_limits` 表与 007000 基线迁移所播种选项的问题——该缺失导致全新安装的 API 限流静默失效、数据保留清理默认关闭。
- **Linux 兼容**：类加载改为基于真实目录清单的大小写无关解析（`class.SignManager.php` 等混合命名文件在 Linux 容器不再报错），新增静态回归测试。

## 🔧 改进与优化

- **调度可靠性**：`runOnce` 排程写入持锁完成（finally 保证释放），消除并发交错窗口；渠道告警去重，新增 `cron_notify_interval`（默认 3600 秒，0 关闭），持续失败任务的 Webhook/通知最多每窗口一次，结构化错误日志不受影响。
- **备份恢复演练**：新增 `tools/backup-restore-drill.php`（15 项断言，真实数据库），每次 CI 自动执行「全新安装 → 播种 → 备份 → 空库恢复 → 15 张表逐行指纹比对」完整演练。
- **发布门禁**：新增一键发布门禁 `tools/release-gate.php`（`composer gate`），语法扫描、单元测试、版本元数据一致性、迁移文件规范、入口 SQL 注入面守卫、四条数据库集成链路一次跑完；CI 新增 Windows 发布打包作业，发布包生产线进入回归范围。
- **CI**：新增 Docker 镜像冒烟（构建并 `compose up --wait`，验证 `healthz.php` 与首页路由）；`composer integration` 覆盖迁移/调度/API/备份恢复四条链路。
- 发布脚本新增 `-CleanOldReleases <N>` 与 `-DeleteOldTags`（显式开关），本地打包模式不做任何远端变更。

## 🧪 验证结果

- 单元测试全量 105 项通过（含 `MigratorTest` 14 项、`ReleaseConfigTest` 7 项、`UpdaterTest` 新增 5 项摘要校验）。
- 真实数据库集成测试：迁移（35 项断言）、调度（43 项断言）、API（20 项断言）、备份恢复演练（15 项断言），在 CI 的 MariaDB 11.4 服务容器中运行。

## 🔄 升级与数据迁移

1. **备份数据库**并确认备份可恢复。
2. 覆盖程序文件后访问站点，版本门禁会引导到升级入口；或执行 `php tools/migrate.php up`。新选项 `cron_notify_interval` 由迁移 007100 自动写入。
3. 5.13 及更早版本请先通过 `setup/update.php` 逐步升级到 6.6，再升级到 7.0。
