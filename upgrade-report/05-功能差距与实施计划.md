## 3. P0/P1 差距与引入方案

### 3.1 任务调度（P0）

当前项目已有 `cron` 表与 `do.php` 定时执行机制，但缺少可视化任务管理、失败重试、运行日志和手动触发。

| 参考项目 | Stars | 借鉴点 |
|----------|------:|--------|
| `xuxueli/xxl-job` | 30.4k | 任务分组、调度日志、失败重试 |
| `jhuckaby/Cronicle` | 5.8k | Web UI 管理任务、运行历史 |
| `PowerJob/PowerJob` | 7.8k | 调度模型、任务状态机 |
| `dagucloud/dagu` | 3.7k | 本地优先工作流、声明式配置 |
| `healthchecks/healthchecks` | 10.2k | 任务心跳监控、状态页 |

实施建议：

1. 保留现有 cron 触发入口，新增 `cron_log` 表记录每次执行时间、状态、耗时、错误。
2. 后台增加“任务列表 / 手动执行 / 暂停 / 重试”页面。
3. 单任务失败按指数退避重试，连续失败发送通知。
4. 不引入 Java/Node 调度框架，避免改变部署形态；可参考其 UI 与状态模型。

### 3.2 签到自动化（P0）

当前核心已实现百度贴吧自动签到，主要差距是执行韧性、账号健康度与扩展性。

| 参考项目 | Stars | 借鉴点 |
|----------|------:|--------|
| `Sitoi/dailycheckin` | 8.7k | 多平台适配、签到结果汇总、Docker 部署 |
| `MoeNetwork/Tieba-Cloud-Sign` | 2.0k | 本项目上游，签到协议与插件生态 |
| `wd210010/only_for_happly` | 1.4k | 多平台签到脚本整合 |
| `qd-today/qd` | 5.6k | HAR 驱动的请求任务、可视化配置 |

实施建议：

1. 先做签到核心现代化：统一结果码、超时、重试、UA 池、签到间隔控制。
2. 增加“账号健康度”概念：BDUSS 失效自动标记并通知，而不是继续静默失败。
3. 保持 PHP + 现有表结构，外部项目只作为协议/交互参考，不直接拷贝 Python/Java 代码。
4. 对 `Sitoi/dailycheckin` 等成熟脚本，可评估将其作为独立旁路容器部署，由主系统调度并展示结果，而不是侵入式合并。

### 3.3 管理后台 UI（P1）

| 参考项目 | Stars | 借鉴点 |
|----------|------:|--------|
| `ColorlibHQ/AdminLTE` | 45.5k | 侧边栏、顶栏、统计卡片、布局骨架 |
| `ColorlibHQ/gentelella` | 21.4k | 管理后台视觉体系 |
| `coreui/coreui-free-bootstrap-admin-template` | 12.2k | Bootstrap 5 组件、暗色模式 |
| `adminkit/adminkit` | 1.7k | 轻量后台模板 |

实施建议：

1. 只取模板的布局与组件，不整体搬入模板源码。
2. 集成时保留对应仓库 LICENSE 与版权声明，裁剪后补充 `THIRD_PARTY_NOTICES.md`。
3. 与 [02-UI升级方案.md](./02-UI升级方案.md) 的 Token 化、暗色模式、响应式改造合并推进。

## 5. 安全差距（与对标结果合并）

| 问题 | 位置 | 建议 |
|------|------|------|
| 安装脚本仍写入 `md5(md5(md5($pwd)))` | `setup/install.php:184` | 安装时改用 `password_hash(..., PASSWORD_BCRYPT, cost=12)`，与 `P::pwd()`/`pwd_verify()` 保持一致 |
| 旧密码哈希兼容 | `P::pwd()` 已有 `pwd_verify()` | 保留 legacy 校验，登录成功后自动升级为新哈希 |
| 登录入口缺少限流 | `templates/login.php` 流程 | 增加失败次数锁定、验证码、审计日志 |
| 安装入口 | `setup/install.php` | 默认启用 `install.lock` 自动创建，公网部署必须确认 |
| CSRF | `config.php` 已支持 `CSRF=true` | 保持默认开启，并在插件表单统一校验 |

## 6. 外部代码集成规则

1. 每次集成前核对上游仓库 LICENSE、版权声明与依赖许可。
2. 复制到项目内的文件必须保留原 LICENSE、NOTICE、作者署名。
3. 新增 `THIRD_PARTY_NOTICES.md` 记录仓库地址、版本、许可证、修改说明。
4. 优先采用“参考实现 + 自研适配”，避免整体搬运大框架。
5. 每个功能集成后执行 `docker compose build && docker compose up -d`，并完成对应页面冒烟。
