# 03 性能全面升级方案 - 百度贴吧云签到

- 编制日期：2026-08-04
- 当前状态：基线已实测，优化方案待实施
- 测量环境：本机 Docker Compose（`web` + `db` 均 healthy），访问 `http://127.0.0.1:8080`

---

## 1. 性能基线

### 1.1 页面与静态资源（本机实测，2026-08-04）

| 资源 | HTTP 状态 | TTFB | 原始大小 | gzip 后大小 |
|------|-----------|------|----------|-------------|
| `http://127.0.0.1:8080/` | 302（未登录跳转） | 约 8.3ms | 约 4.5 KB | - |
| `index.php?mod=login` | 200 | 约 6.0ms | 约 5.0 KB | - |
| `source/js/jquery.min.js` | 200 | 约 2.9ms | 89,795 B | 32,333 B |
| `source/css/bootstrap.min.css` | 200 | 约 3.1ms | 121,457 B | 21,163 B |
| `source/js/js.js` | 200 | - | 11,011 B | 3,057 B |
| `source/js/bootstrap.min.js` | 200 | - | 39,680 B | - |

首屏关键静态资源合计：JS 约 140 KB、CSS 约 121 KB，gzip 后约 56 KB；请求数偏多（jQuery、Bootstrap CSS/JS、`js.js`、`ui.css`、`my.css`、`my.js` 等），且 `my.css`/`my.js` 为占位空文件。

### 1.2 传输与缓存现状

- Caddy 已启用 `encode gzip`：实测 Bootstrap CSS 121,457 B -> 21,163 B，jQuery 89,795 B -> 32,333 B。
- 已启用安全响应头：`X-Content-Type-Options`、`Referrer-Policy`、`X-Frame-Options`。
- 静态资源有 `ETag` / `Last-Modified`，但**无 `Cache-Control` 强缓存头**。
- 资源 URL 无版本号（如 `jquery.min.js` 不带 `?v=` 或哈希名），更新文件后浏览器可能缓存旧版本。
- 未启用 Brotli/zstd 压缩。
- OPcache 已在 Dockerfile 中启用：`opcache.enable=1`、128 MB、10000 文件上限。
- PHP-FPM 为 `ondemand`，`pm.max_children=75`，当前小规模运行足够。

### 1.3 数据库现状

- MariaDB 11.4，7 张表均为 **MyISAM**：`baiduid`、`cron`、`options`、`plugins`、`tieba`、`users`、`users_options`。
- 当前数据量很小（`cron` 2 行、`options` 50 行、`users` 1 行），性能问题尚未暴露。
- 未开启慢查询日志，无显式索引审计记录。

## 2. 优化清单

| # | 优化项 | 优先级 | 预期收益 | 实施成本 |
|---|--------|--------|----------|----------|
| 1 | 静态资源加 `Cache-Control`（版本化后 `max-age=31536000, immutable`） | P0 | 减少重复加载，二次访问静态资源近乎零网络成本 | 低（Caddy 配置） |
| 2 | 资源 URL 版本化（`?v=哈希` 或构建时哈希文件名） | P0 | 避免缓存穿透与旧资源混合 | 低 |
| 3 | 启用 Brotli/zstd 压缩（Caddy `encode zstd gzip`） | P1 | gzip 基础上再降约 10-20% | 低 |
| 4 | 合并/精简 CSS 与 JS，移除 `my.css`/`my.js` 空请求 | P1 | 减少 2 个请求与解析开销 | 低 |
| 5 | JS 加 `defer`，避免阻塞首屏解析 | P1 | 改善 LCP/INP | 低 |
| 6 | 清理并迁移未激活插件内大体积 CSS（约 420 KB） | P1 | 减小部署体积与误加载风险 | 低（需确认） |
| 7 | 图片/字体裁剪：Glyphicons 多格式字体按需保留，教程图转 WebP | P2 | 减少约 20-40 KB 资源 | 中 |
| 8 | MyISAM 转 InnoDB + 补充 `cron`/`baiduid`/`users` 常用查询索引 | P2 | 行锁、崩溃恢复、并发写入更稳 | 中（需备份与验证） |
| 9 | 开启 MySQL 慢查询日志与基础监控 | P2 | 提前发现 N+1 与全表扫描 | 低 |
| 10 | PHP-FPM 参数按真实并发压测微调 | P3 | 避免峰值时 502/超时 | 低 |
| 11 | 生产环境启用 Caddy 自动 HTTPS（HTTP/2、HTTP/3） | P3 | 多路复用、连接复用、性能与安全双提升 | 低-中 |
| 12 | 可选 CDN 分发静态资源 | P3 | 多地域访问更快 | 中 |

## 3. Caddy 配置示例

```caddyfile
:8080
root * /var/www
encode zstd gzip

@static path /source/* /favicon.ico
header @static Cache-Control "public, max-age=31536000, immutable"

header {
    X-Content-Type-Options nosniff
    Referrer-Policy same-origin
    X-Frame-Options SAMEORIGIN
}

php_fastcgi 127.0.0.1:9000
file_server
```

注意事项：

- 加版本号后静态资源才能安全使用 `immutable`；未版本化的 `source/` 目录不建议直接一年强缓存。
- 版本化可采用 `?v=<git 提交哈希>` 或文件名哈希，优先在 `lib/ui.php` 中集中定义常量，避免逐页手改。
- 启用 Brotli/zstd 后建议实测各资源压缩前后大小，避免对极小文件产生无意义开销。

## 4. 数据库改造建议

1. 备份 `mysql_data` 卷后，逐表执行 `ALTER TABLE ... ENGINE=InnoDB;`。
2. 优先加索引：
   - `cron(id, nextrun, type, enable)` 或与现有 cron 查询匹配的组合索引。
   - `baiduid(uid)`、`tieba(uid, name)`、`users_options(uid)`。
3. 开启慢查询日志：
   ```ini
   slow_query_log=1
   slow_query_log_file=/var/log/mysql/mariadb-slow.log
   long_query_time=1
   ```
4. 若后续接入任务调度中心，考虑把任务执行状态独立成 `cron_log` 表，避免查询放大。

| 指标 | 当前 | 目标 |
|------|------|------|
| 登录页 TTFB | 约 6ms | 保持 < 50ms（本地基线，主要看后端稳定性） |

| 大列表页（千级账号/贴吧） | 未压测 | 单页 < 200ms 后端响应，无阻塞查询 |
| Lighthouse Performance | 未跑 | ≥ 90（生产 HTTPS 环境） |

## 6. 测量与验收

- 每次改动后用 `curl.exe` 记录 TTFB、状态码、原始/压缩体积。
- 关键页面：登录页、控制台首页、账号绑定页、贴吧列表、设置页、插件页。
- Docker 侧：`docker stats` 观察 web/db 容器 CPU 与内存；`docker compose logs` 看 FPM 超时与错误。
- 上线前在生产 HTTPS 域名跑一次 Lighthouse 五项，建立完整基线；本地 HTTP 站点不直接作为 Lighthouse 最终评分依据。
- 每次构建后必须执行 `docker compose build && docker compose up -d`，并用管理员账号完成登录与页面冒烟。
