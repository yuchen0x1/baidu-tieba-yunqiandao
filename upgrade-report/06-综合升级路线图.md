## 1. 总体结论

项目运行基础已经现代化（PHP 8.4、MariaDB 11.4、Docker Compose V2、Caddy、CSRF、OPcache），当前 `web`/`db` 容器均 healthy，`http://127.0.0.1:8080` 可访问。主要遗留问题集中在三层：

1. **UI 层**：Bootstrap 3 + 283 处内联样式 + 占位资源，维护成本和移动端体验差。
2. **功能层**：任务调度无可视化/日志/重试，签到核心韧性不足，缺少监控与通知。
3. **工程层**：无前端构建工具、无自动化测试、数据库仍为 MyISAM、安装脚本密码哈希未统一、项目目录无 `.git` 版本控制。

建议采用“**短期清理 + 中期 UI/性能 + 长期功能演进**”的增量路线，不做 React/Vue 全量重写。

## 4. 风险登记表

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 项目无 `.git`，误改无法回溯 | 高 | 阶段 0 先建库提交，所有操作前备份 |
| 无自动化测试，回归靠手工 | 中高 | 每页冒烟清单；后续为 `do.php`/登录/绑定补最小测试 |
| MyISAM 转 InnoDB 出现锁表/存储差异 | 中 | 备份后逐表迁移，验证 cron 执行 |
| 插件生态依赖 Bootstrap 3 类名 | 中 | 保留旧 CSS fallback，分页迁移，不一次性切换 |
| 外部模板/库 LICENSE 遗漏 | 中 | 集成前核验，统一写入 `THIRD_PARTY_NOTICES.md` |
| 任务调度改造破坏现有 cron | 中高 | 新旧机制并行一周期，`cron_log` 对账 |
| 登录/安全改造影响老用户 | 中 | 保留 legacy 哈希校验，登录后升级为新哈希 |
| 无前端构建工具，资源管理散乱 | 中 | 先统一 `lib/ui.php` 资源入口，再决定是否引入轻量构建 |
| 范围蔓延（图表/插件/多平台） | 中 | 严格按 P0-P3 分批，每批验收后再开下一批 |

## 5. 每个功能的强制验收流程

```powershell
# 1. 构建
cd C:/Users/LENMO\Desktop\百度贴吧云签到\docker
docker compose build

# 2. 启动
docker compose up -d
docker compose ps

# 3. 冒烟
curl.exe -s -o NUL -w "%{http_code} %{time_starttransfer}s\n" http://127.0.0.1:8080/index.php?mod=login
```

手工冒烟清单：

- 管理员登录、登出。
- 绑定百度账号（至少到二维码页）。
- 贴吧列表与签到记录展示。
- 设置保存后刷新仍生效。
- 插件启用/禁用无白屏。
- cron 手动执行一次并查看日志。
- 暗色模式与移动端无样式错乱。
