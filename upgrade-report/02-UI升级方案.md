# 02 UI 全面升级方案 - 百度贴吧云签到

- 编制日期：2026-08-04
- 当前状态：分析方案已完成，未修改业务 UI 代码
- 目标：在不推翻 PHP 单体架构的前提下，把 Bootstrap 3 时代界面升级为现代、统一、可维护、无障碍的管理工具界面

---

## 1. 当前 UI 状况审计

| 审计项 | 现状 |
|--------|------|
| 全局样式入口 | `lib/ui.php` 加载 `bootstrap.min.css`、`ui.css`（798 B）、`my.css`（26 B 占位注释） |
| 组件库 | Bootstrap 3.4.1（已停止维护多年） |
| JS 依赖 | jQuery 3.6.4 + Bootstrap 3 JS + `js.js`（11,011 B） |
| 内联样式 | 283 处 `style="..."`，存在大量硬编码像素值与颜色 |
| 表单控件 | 293 个 `input/select/textarea`，仅 119 个具备 `id` 或 `aria-*` 关联线索 |
| CSS 变量 | 0 |
| 暗色模式 | 无 |
| 响应式 | 仅有 Bootstrap 3 基础栅格，表格/导航在移动端易溢出 |
| 图标 | Bootstrap 3 Glyphicons + 少量内联字符/图片，方案不统一 |
| 状态反馈 | 无统一 Loading/Empty/Error 组件，多为原生 alert |
| 无障碍 | 未达到 WCAG 2.1 AA，焦点样式、label 关联、键盘导航均不足 |
| 字体 | 全局 `微软雅黑` + Bootstrap 默认字体，标题层级不明显 |

## 2. 主要问题清单

1. Bootstrap 3 已停止维护，安全补丁与浏览器兼容策略落后。
2. 硬编码颜色/间距/字号分散在 283 处内联样式中，无法做全局主题切换。
3. `my.css`/`my.js` 是空占位文件，却由 `lib/ui.php` 全局加载，每页产生 2 个多余请求。
4. 表单大量缺少 `<label>`、`aria-describedby`、`aria-invalid`，屏幕阅读器难以使用。
5. 表格类页面（账号列表、贴吧列表、插件列表）在小屏上直接横向溢出。
6. 成功/失败提示依赖 Bootstrap 3 `alert`，视觉层级和可访问性不足。
7. 无骨架屏、无加载中态、无空态，操作反馈不明确。
8. 图标混用 Glyphicons、emoji、图片和字符符号，替换成本高。

## 3. 设计 Token 化方案

先在根目录增加 `source/css/tokens.css`（CSS 变量），再逐步替换 `ui.css` 和内联样式。Token 只定义语义，不直接写死颜色。

| Token | 值（推荐） | 用途 |
|-------|-----------|------|
| `--color-primary` | `#1a73e8` | 主操作、链接、选中态 |
| `--color-primary-hover` | `#1765cc` | 主操作 hover |
| `--color-success` | `#188038` | 成功、签到完成 |
| `--color-warning` | `#b06000` | 警告、待处理 |
| `--color-danger` | `#d93025` | 错误、封禁、删除 |
| `--color-info` | `#0b57d0` | 信息提示 |
| `--color-bg` | `#f6f8fa` | 页面背景 |
| `--color-surface` | `#ffffff` | 卡片/面板/表格背景 |
| `--color-border` | `#d0d7de` | 边框、分隔线 |
| `--color-text` | `#1f2328` | 主文本 |
| `--color-text-secondary` | `#57606a` | 次要文本 |
| `--color-text-disabled` | `#8c959f` | 禁用态 |
| `--space-1` | 4px | 最小间距 |
| `--space-2` | 8px | 紧凑间距 |
| `--space-3` | 12px | 控件内边距 |
| `--space-4` | 16px | 面板内边距 |
| `--space-5` | 24px | 区块间距 |
| `--radius-sm` | 4px | 输入框、小按钮 |
| `--radius-md` | 6px | 面板、表格 |
| `--radius-lg` | 8px | 弹窗、卡片（管理工具保持克制，不超过 8px） |
| `--shadow-sm` | `0 1px 2px rgba(31,35,40,.06)` | 轻量层级 |
| `--shadow-md` | `0 4px 12px rgba(31,35,40,.08)` | 下拉、弹窗 |
| `--font-sans` | `"Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif` | 全局字体栈 |
| `--font-mono` | `"Cascadia Code", Consolas, monospace` | 日志、BDUSS、SQL 等 |
| `--z-dropdown` | 1000 | 下拉 |
| `--z-modal` | 1050 | 弹窗 |
| `--z-toast` | 1100 | 提示 |
| `--transition-fast` | 120ms | hover/active |
| `--transition-base` | 200ms | 展开/收起 |

示例接入方式：

```css
:root {
  --color-primary: #1a73e8;
  --space-4: 16px;
  --radius-md: 6px;
}
```

改造顺序：

1. 新增 `tokens.css`，在 `bootstrap.min.css` 之后加载。
2. 把 `ui.css` 中 798 B 的现有规则改为引用 Token。
3. 283 处内联样式按“先高频、后低频”迁移到语义 class。
4. 检查最终 CSS 色板，避免大面积单一色系，确保界面克制、可扫读。

## 4. 组件库升级路径

推荐路径：**Bootstrap 3 -> Bootstrap 5（或直接基于 AdminLTE 4 模板）**，不引入 React/Vue 全量重写。

| 方案 | 优点 | 成本 |
|------|------|------|
| A：直接升级 Bootstrap 5 | 依赖少、改动可控、官方长期维护 | 需重写少量类名，表单/按钮 API 变化 |
| B：基于 AdminLTE 4 模板改造 | 获得侧边栏、顶栏、统计卡等成熟后台结构 | 模板文件较大，需裁剪；集成时保留模板 LICENSE |
| C：全量前端重写（React/Vue） | 组件体系最现代 | 与现有 PHP 模板机制冲突最大，不建议作为当前阶段方案 |

建议采用 **B 为主、A 为辅**：先提取 AdminLTE/CoreUI 的布局骨架，再以 Bootstrap 5 为基础构建统一组件。

升级时注意：

- `lib/ui.php` 的 `loadhead()` 是全局入口，所有页面共用；组件库升级只需改这一处加载链路。
- 模板目录 `templates/` 共 16 个模板，全部由 `template()` 函数加载，可逐页迁移。
- Bootstrap 3 的 `panel`、`well`、`input-group-addon` 等类在 Bootstrap 5 中已改名，需先做类名映射表。
- 迁移期间保留旧 CSS 文件作为 fallback，逐页切换，不一次性全量替换。

## 5. 暗色模式

- 方案：CSS 变量 + `[data-theme="dark"]` + `prefers-color-scheme: dark`。
- 页面根节点由 `loadhead()` 输出 `data-theme` 属性，用户手动选择后写入 `localStorage`。
- 暗色 Token 只需覆盖颜色族，不改变间距/圆角/阴影语义。
- 所有颜色对比度按 WCAG 2.1 AA 校验：正文至少 4.5:1，大字号/UI 组件至少 3:1。
- 对图表、二维码、验证码图片等非 CSS 资源，提供暗色兼容容器（如二维码白底黑块，不强制反色）。
- 过渡动画使用 `prefers-reduced-motion: reduce` 时关闭。

## 6. 响应式与移动端补全

| 页面类型 | 移动端问题 | 改造措施 |
|----------|-----------|----------|
| 控制台首页 | 统计卡片挤压 | 改 2 列/单列流式卡片 |
| 贴吧列表/账号列表 | 表格横向溢出 | 小屏切换为卡片列表，保留核心字段 |
| 设置表单 | 多列表单错位 | 表单字段改为单列，操作按钮吸底或置顶 |
| 导航 | 顶部导航拥挤 | 小屏使用折叠式侧边栏/汉堡菜单 |
| 弹窗 | 宽度超出视口 | 弹窗最大宽度 92vw，内容可滚动 |

断点沿用 Bootstrap 5：`sm ≥ 576px`、`md ≥ 768px`、`lg ≥ 992px`、`xl ≥ 1200px`。

## 7. Loading / Empty / Error 状态

- Loading：按钮提交时禁用并显示 spinner；列表页使用轻量骨架行，避免整页闪烁。
- Empty：所有列表提供“无数据”状态与下一步动作（如“添加贴吧账号”）。
- Error：表单错误显示字段级提示（`aria-invalid` + 文本），接口错误显示统一 Error 面板。
- 所有状态组件收进 `source/css/ui.css` 或独立 `components.css`，禁止每个页面复制样式。

## 8. 无障碍（WCAG 2.1 AA）

| 检查项 | 目标 |
|--------|------|
| 语义化 | 使用 `<main>`、`<nav>`、`<h1-h6>`、`<table>`/`caption` |
| label | 293 个表单控件补齐 `<label for>` 或 `aria-label` |
| 焦点 | 全局可见 `:focus-visible` 样式，Tab 顺序符合操作流 |
| 键盘 | 下拉、弹窗、折叠面板支持 Esc 关闭与方向键操作 |
| aria | 弹窗用 `role="dialog"` + `aria-modal`，错误用 `role="alert"` |
| 对比度 | 文本 4.5:1，UI 组件 3:1 |
| 动效 | `prefers-reduced-motion` 关闭非必要动画 |
| 表单验证 | 错误信息与控件关联，不只用颜色表达 |

## 9. 字体与图标

- 字体栈使用系统字体优先，避免为管理后台引入大型 web font。
- 标题字号保持层级：页面标题约 20-22px，卡片标题 15-16px，正文 14px。
- 图标统一为 Bootstrap Icons 或 Font Awesome 6（二选一），替换现有 Glyphicons 和 emoji 混用。
- 图标用于按钮/状态时必须有 `aria-hidden="true"` 与可读文本；纯图标按钮加 `title`/`aria-label`。
